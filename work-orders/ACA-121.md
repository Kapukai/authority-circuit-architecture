# ACA-121 — Authority Cell Canonical Graph

Status: PROPOSED

## Purpose

Define the canonical graph object underlying every ACA view without replacing the existing ACA-120 Verifiable Authority Cell.

## Inputs

- ACA-100 Authority Circuit Architecture
- ACA-110 Core Terminology
- ACA-120 Verifiable Authority Cell
- ACA-130 Decision State Machine
- ACA-140 Decision Proof Record
- ACA-150 Operationalized Remedy Protocol

## Deliverables

1. Canonical Authority Cell graph schema.
2. Stable identity rules for cells, evaluations, nodes, edges, sources, events, and projections.
3. Node taxonomy covering sovereign source, constitutional grant, structural allocation, statute, delegation, jurisdiction, predicate, procedure, instrument, actor, execution, affected subject, review, and remedy.
4. Edge taxonomy covering grant, allocation, enactment, delegation, binding, satisfaction, authorization, execution, challenge, revocation, correction, and remedy.
5. Canonical serialization and hashing rules.
6. Append-only version and correction model.
7. Minimal synthetic example.
8. Deterministic schema and integrity verifier.

## Required separations

The model SHALL distinguish:

- exact source text;
- source metadata;
- human interpretation;
- machine parse;
- human determination;
- authorization;
- execution;
- correction and remedy.

## Acceptance criteria

- Every projection can be regenerated from the canonical cell and declared transformation version.
- No projection stores a conflicting substantive copy of canonical data.
- Node and edge identifiers remain stable across projections.
- Previous versions remain reconstructable.
- Missing support is represented explicitly rather than omitted.
- Schema validity is not represented as substantive legal validity.

## Non-goals

ACA-121 does not determine legality, legitimacy, factual truth, guilt, entitlement, jurisdiction, or permission to act. It does not create a lawfulness score or replace qualified human review.

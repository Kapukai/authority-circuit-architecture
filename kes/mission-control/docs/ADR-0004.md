# ADR-0004 — Mission Control as a Read-Only Control Plane

## Status

Proposed

## Context

Kapukai now contains standards, product candidates, release tooling, repository intelligence, multiple branches, research plans, and an expanding critical path. Repository presence alone does not establish authorization, verification, acceptance, release, or current priority.

## Decision

KES-0004 will implement Mission Control as a read-only program control plane driven by a canonical, versioned program-state record.

Mission Control will separate:

- existence from status;
- verification from acceptance;
- acceptance from publication;
- dependency from authorization;
- recommendation from decision.

The first implementation will use a static browser application and JSON input. It will not require a server, database, autonomous agent, or external package manager.

## Rationale

A static, deterministic candidate minimizes operational risk while proving the information architecture. A canonical state record allows the dashboard to be replayed, reviewed, hashed, and later generated by Repository Intelligence or other governed capabilities.

## Consequences

Positive:

- one visible program map;
- explicit states and dependencies;
- reduced mental load;
- no autonomous repository changes;
- straightforward rollback and review.

Limitations:

- initial state is curated by humans;
- freshness depends on controlled updates;
- the dashboard cannot establish that a claimed state is true;
- GitHub and deployment synchronization remain future integrations.

## Invariant

Mission Control may display and validate program state. It may never authorize or execute a state transition.

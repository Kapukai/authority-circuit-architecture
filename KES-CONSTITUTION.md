# KES Constitution v1.0

## Mission

KES turns verified human needs into verified products through bounded work orders,
explicit capability assignment, independent verification, controlled release, and
preserved learning.

## Chief Architect Law

No work may bypass the critical path. Every work order must reduce the distance
between a verified human need and a working product. Work that does not shorten
that path belongs in the backlog until evidence demonstrates it is necessary.

## Authority

The Chief Architect owns prioritization, architecture, critical-path protection,
acceptance, and release authorization. Capabilities execute work; they do not
silently redefine scope or acceptance criteria.

## Operating cycle

Human need -> Work Order -> Capability Plan -> Implementation -> Independent
Verification -> Human Approval -> Release -> Observation -> Remedy -> Learning.

## Invariants

1. Every material change has a work order.
2. Implementation and verification are separated.
3. Claims are traceable to evidence.
4. Consequential releases require human approval.
5. Secrets never enter source control, logs, prompts, fixtures, screenshots, or DPRs.
6. Platform changes require demonstrated product need.
7. Completed work generates a learning record.
8. Organizational changes require an ADR.

# CONTRIBUTING

Thank you for contributing to Authority Circuit Architecture (ACA).

## Contribution Principles

Contributions should improve observability, reproducibility, interoperability,
auditability, or operational remedy.

Standards text should remain implementation-neutral unless a document is
explicitly identified as a reference implementation or implementation guide.

## Contribution Types

Contributions may:

- clarify specifications;
- correct contradictions or ambiguity;
- improve terminology;
- add reproducible examples;
- add schemas, fixtures, or conformance tests;
- report security or rights-impact concerns;
- propose new standards or profiles.

## Normative Changes

Every normative change should identify:

1. the problem being corrected;
2. the affected requirement identifiers;
3. the proposed change;
4. the rationale;
5. backward-compatibility impact;
6. security, rights, and remedy implications;
7. at least one test case or reproducible example, where applicable.

## Normative Language

Use the key words `MUST`, `MUST NOT`, `SHOULD`, `SHOULD NOT`, and `MAY`
only for requirements that can be objectively tested.

Normative and informative content should be clearly distinguishable.

## Pull Requests

Each pull request should be focused and include:

- a concise problem statement;
- the proposed change;
- the reason for the change;
- compatibility implications;
- tests, fixtures, or examples where applicable;
- any unresolved questions.

## Review

Review should evaluate:

- specification clarity;
- reproducibility;
- conformance impact;
- security impact;
- human-rights and remedy impact;
- interoperability;
- implementation burden.

## Contributor Conduct

Participation is governed by `CODE_OF_CONDUCT.md`.
Security vulnerabilities should be reported according to `SECURITY.md`.
